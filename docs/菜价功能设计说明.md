# 菜价功能设计说明

## 1. 功能定位

菜价功能用于记录家庭实际购买价格，并在再次购物时快速回答三个问题：

1. 这个商品以前买过多少钱？
2. 不同店铺的价格和品质有什么差异？
3. 手上商品的单位不一致时，当前价格是否合适？

该功能集成在现有 App 的底部“菜价”导航中，首页标题统一为“记录菜价”。它是家庭自己的价格记录工具，不做公共比价平台、促销信息聚合或复杂商品管理。

设计原则：

- 购买现场优先：尽量少填，适合单手连续录入。
- 数据可信优先：统一单位、保留时间，并允许纠错。
- 历史可比较：同一商品可比较不同店铺，也可查看单店趋势。
- 品质轻量化：只使用 1～5 星，不增加品质维度或标签。
- 非必填项延后：品质和原价都不阻塞现场记录。

## 2. 页面结构

```text
菜价首页（记录菜价）
├── 搜索商品
├── 常用商品
├── 最近记录（含已评价与未评价）
├── 商品价格详情
│   ├── 各店最新价格
│   ├── 现场比价
│   ├── 价格趋势
│   └── 历史记录与纠错
└── 记录菜价
    ├── 店铺搜索、添加与常用店铺
    ├── 商品搜索、添加与常用商品
    ├── 按单价 / 按总价录入
    ├── 日常价 / 优惠价
    └── 保存 / 保存并新增
```

## 3. 菜价首页

首页标题为“记录菜价”，包含以下区域：

### 3.1 商品搜索

- 搜索已有商品，结果显示商品名称、涉及店铺数、最近记录时间和最新价格区间。
- 点击结果进入商品价格详情。
- 搜索为空时展示常用商品和最近查看商品，不展示空白结果页。
- 没有匹配商品时提供“添加商品‘输入内容’”，添加后直接用于本次记录。

### 3.2 常用商品

- 最多展示 8 个，按近 30 天记录次数从高到低排序；次数相同时，最近使用的排在前面。
- 新增商品在被频繁使用后可自动进入常用区，不维护固定名单。
- 常见商品优先使用阿里巴巴 Iconfont 中轮廓清晰、容易辨认的现成 SVG，例如肉排、鸡腿、鱼、蛋、叶菜、番茄、水果、米面、奶和饮料；不自行绘制业务图标。没有专属图形时使用大类图形，再没有时使用商品名称首字作为回退。
- 前端资源保留每个 Iconfont 素材的公开条目 ID，便于核对来源或后续替换；当前预设覆盖肉类、水产、蛋奶、果蔬、粮油、面点、豆制品、菌菇和调味料。
- 商品图标只辅助识别，不参与商品是否相同的判断。

### 3.3 最近记录与品质评价

- 该区域固定放在首页内容最下方，展示最近购买记录，不因补充品质评分而消失。
- 每条展示商品、店铺、购买日期、购买数量或总价、统一单价，并可直接选择或修改 1～5 星。
- 用户可以暂不评价，不发送强制通知，不影响价格记录。
- 品质评分属于一次具体购买记录，而不是永久定义某个商品或店铺。

### 3.4 主操作

- 首页提供明显的“记录菜价”按钮。
- 点击后进入记录页；从商品详情进入时自动带入商品，从现场比价进入时自动带入商品和价格信息。

## 4. 搜索、添加与重复数据

商品和店铺使用相同的轻量搜索规则：

1. 输入框获得焦点时，先展示常用或最近使用项。
2. 输入时在本地已有数据中即时过滤，最多展示 5 个结果。
3. 完全匹配已有名称时只提供选择，不重复创建。
4. 没有完全匹配时，在结果末尾展示“添加商品”或“添加店铺”。
5. 搜索图标位于输入框内部固定区域，文字始终保留足够左边距，不能与图标重叠。
6. 选择结果或完成添加后关闭建议列表，避免遮挡后续字段。

第一版只做名称包含匹配。后续数据出现“番茄/西红柿”“里脊/猪里脊”或录入错别字时，再增加商品重命名、别名和合并能力；不在首次实现中引入复杂分类系统。

## 5. 记录菜价

### 5.1 店铺

- 店铺支持搜索已有项，不存在时直接添加。
- 店铺名称允许直接包含分店，例如“永辉超市·金科店”，不增加必填的分店字段。
- 分店名称以已知品牌开头时沿用品牌图标，但价格记录仍按完整店铺名称分别统计，避免不同分店价格混在一起。
- 常用店铺最多展示 8 个，按近 30 天记录次数排序；次数相同时按最近使用时间排序。
- 新增的“重百”等店铺在使用次数超过末位后，自动进入常用店铺。

常用店铺的图标规则：

| 店铺 | 图标 |
|---|---|
| 永辉超市 | Iconfont 永辉图标（ID `6026423`） |
| 盒马 | Iconfont 盒马生鲜图标（ID `18166608`） |
| 条马 | 条马官网品牌 Logo（来源 `https://www.tiaoma.shop/home`） |
| 新世纪超市 | 未找到可靠品牌素材时使用“新”字 |
| 菜市场 | Iconfont 菜市场图标（ID `18667120`） |
| 路边摊 | Iconfont 小摊贩图标（ID `39440917`） |
| 客百年 | “客”字图标 |
| 钱大妈 | “钱”字图标 |
| 其他店铺 | 店铺首个汉字或通用店铺图标 |

店铺品牌图标只采用可核对的现成素材；搜索结果与品牌不一致时不使用相似图形冒充，直接按上述汉字规则回退。

### 5.2 商品

- 商品支持搜索已有项，不存在时直接添加。
- 商品输入框下展示动态常用商品，排序规则与菜价首页一致。
- 连续记录时，保存上一项后自动聚焦商品输入框，便于立即录入下一项。

### 5.3 价格录入方式

记录页提供两种互斥方式：

#### 按单价

- 输入单价并选择计价单位。
- 可选填本次实际购买数量；填写后记录购买量并同步展示本次合计，旧记录或不知道购买量时可留空。
- 支持 `元/克`、`元/千克`、`元/斤`、`元/毫升`、`元/升`、`元/个`、`元/盒`和`元/瓶`。
- 页面同步展示统一换算结果，例如输入 `32 元/千克` 后显示“折合 16 元/斤”。

#### 按总价

- 输入总价、数量和数量单位。
- 数量单位支持克、千克、斤、毫升、升、个、盒和瓶。
- 页面自动计算统一单价，例如 `39.8 元 ÷ 1.2 千克` 显示“折合 16.58 元/斤”。

换算规则：

- `1 千克 = 2 斤 = 1000 克`。
- `1 升 = 1000 毫升`。
- 个、盒、瓶只在相同单位内比较，不能自动与重量或容量互换。
- 金额显示保留最多两位小数；计算使用未截断值，避免连续换算误差。

### 5.4 价格类型

价格类型使用“日常价 / 优惠价”分段选择，不使用复选框式描述。

- 默认选择“日常价”。
- 选择“优惠价”后才显示“原价（选填）”。
- 用户不知道原价时可直接留空，优惠价记录仍然有效。
- 原价必须带单位，默认跟随本次录入的单位，并允许修改。
- 不记录优惠条件、优惠类型和截止日期。

### 5.5 记录时间

- 默认使用当前时间，不要求用户现场填写。
- 支持修改日期和时间，用于补录较早购买记录。
- 查询页和趋势图均使用购买时间，不使用后续补充品质的时间。

### 5.6 输入校验

- 商品、店铺、价格为必填项。
- 金额和数量必须大于 0；按总价录入时数量不能为空。
- 两种录入方式都必须在保存前展示标准化后的单价。
- 当标准化价格明显偏离该商品历史价格时给出非阻断提醒，重点防止把“元/千克”误选成“元/克”等单位错误。
- 异常提醒只要求再次确认，不禁止保存真实的极端优惠或高品质商品。

### 5.7 保存与连续记录

记录页提供两个操作：

- “保存”：保存当前记录并离开记录页。
- “保存并新增”：保存当前记录后继续录入下一项。

执行“保存并新增”后：

- 保留当前店铺，符合一次购物通常发生在同一店铺的场景。
- 清空商品、单价、总价和数量。
- 价格类型恢复为“日常价”，原价字段隐藏并清空，避免优惠状态误带到下一件商品。
- 默认计价单位保留上一次选择，减少连续录入同类商品的操作；用户仍可立即切换。
- 自动聚焦商品输入框并展示常用商品。
- 顶部累计显示“本次已记录 N 项”。
- 保存成功提示中提供“撤销”，撤销后恢复刚才的表单内容。

## 6. 商品价格详情

商品详情用于回答“这个商品现在大概多少钱”和“去哪家买更合适”。

### 6.1 价格摘要

- 所有可换算的重量价格统一显示为元/斤，容量价格统一显示为元/升。
- 价格区间只取每家店最新的一条有效记录，再计算这些最新记录中的最低价和最高价。
- 不使用全部历史记录的最低价和最高价，避免旧价格误导当前判断。
- 超过 30 天的最新记录标注“较早记录”，但不自动删除。
- 数量型商品只比较相同单位，例如元/盒不与元/个合并为同一区间。

### 6.2 店铺列表

每个店铺卡片展示：

- 店铺名称和图标。
- 最新标准化单价。
- 购买日期和记录成员。
- 若为优惠价，显示“优惠价”；有原价时同时展示原价，没有原价时显示“无原价”。
- 对应购买记录的品质星级；未评价时提供“补充品质”。

不同店铺按最新价格从低到高排列；较早记录不隐藏，但应在视觉上弱化。价格和品质并列展示，不计算模糊的“性价比分数”，由用户自行判断。

### 6.3 历史记录与纠错

- 商品详情可展开查看按时间倒序排列的历史购买记录。
- 每条历史记录支持编辑和删除。
- 编辑价格、单位、店铺或时间后，重新计算详情摘要和趋势图。
- 删除前二次确认；删除后短时间内可撤销。
- 家庭成员默认都可以纠正菜价记录，不沿用早睡打卡的双人确认规则。

## 7. 现场比价

现场比价用于处理“手上只有总价和重量”或“标签单位与历史单位不同”的情况。

### 7.1 输入方式

- “按单价”：输入标签单价，并选择元/千克、元/斤或元/克；容量商品支持元/升和元/毫升。
- “按总价”：输入总价、重量或容量，并选择对应单位。
- 结果统一换算为该商品详情页正在使用的标准单位。

### 7.2 比价结果

- 显示换算后的标准单价。
- 与各店最新价格比较，说明比当前最低价高或低多少。
- 如果换算价位于历史最新区间内，可同时展示相对最低店和最高店的差额。
- 比较信息必须带单位，避免把总差额误解为每斤差额。

### 7.3 直接记录

- 结果页提供“记录此价格”。
- 点击后进入记录页，自动带入商品、总价/单价、数量和单位。
- 用户只需确认或选择店铺、价格类型，再保存。
- 从详情页进入时带入当前商品；从其他入口进入时先选择商品。

## 8. 价格趋势

价格趋势在第一版直接提供，不等待记录数量达到某个阈值后才出现。

- 支持“全部店铺”和单个店铺筛选。
- 横轴为购买日期，纵轴使用该商品的标准价格单位。
- 选择全部店铺时，各店分别连线，不计算跨店平均价，也不把不同店铺的数据连成同一条线。
- 优惠价使用独立标记，避免被误解为长期日常价格。
- 数据不足时仍显示入口，并使用“记录不足，继续记录后可查看变化”的空状态。
- 编辑或删除历史记录后立即更新趋势。

## 9. 品质评分

- 品质是购买后的补充项，不出现在现场记录的必填流程中。
- 评分仅为 1～5 星，不区分新鲜度、口感、包装等维度。
- 评分关联具体购买记录，以保留不同批次的真实差异。
- 可从菜价首页“待评价”或商品详情中的店铺记录进入评分。
- 已评分记录允许修改或清除评分。

## 10. 常用排序规则

常用商品与常用店铺使用统一规则：

1. 统计最近 30 天成功保存的记录次数。
2. 次数越多越靠前。
3. 次数相同时，最近使用者靠前。
4. 最多展示 8 个。
5. 新项目达到更高使用频率后自动替换末位项目。
6. 删除一条价格记录后同步修正对应使用次数。

该规则只影响快捷入口顺序，不影响搜索结果和历史数据。

## 11. 最小数据模型

### 11.1 商品

| 字段 | 含义 |
|---|---|
| `id` | 商品 ID |
| `name` | 商品名称 |
| `iconKey` | 可选图标标识 |
| `createdAt` | 创建时间 |

### 11.2 店铺

| 字段 | 含义 |
|---|---|
| `id` | 店铺 ID |
| `name` | 完整店铺名称，可含分店 |
| `brandKey` | 可选品牌图标标识 |
| `createdAt` | 创建时间 |

### 11.3 价格记录

| 字段 | 含义 |
|---|---|
| `id` | 记录 ID |
| `productId` | 商品 ID |
| `storeId` | 店铺 ID |
| `memberId` | 记录成员 |
| `purchasedAt` | 购买时间 |
| `entryMode` | `unit_price` 或 `total_price` |
| `unitPrice` | 按单价录入时的原始单价 |
| `totalPrice` | 按总价录入时的总价 |
| `quantity` | 实际购买数量；按总价录入时必填，按单价录入时可选 |
| `unit` | 原始计价或数量单位 |
| `normalizedPrice` | 换算后的标准单价 |
| `normalizedUnit` | `jin`、`liter`、`piece`、`box` 或 `bottle` |
| `priceKind` | `regular` 或 `discount` |
| `referencePrice` | 可选原价 |
| `referenceUnit` | 可选原价单位 |
| `quality` | 可选 1～5 星 |
| `createdAt` / `updatedAt` | 创建和修改时间 |

标准化价格用于查询、排序和趋势；原始输入同时保留，用于编辑、追溯和避免反向换算丢失信息。

## 12. 必须通过的验收场景

1. 输入 `15 元/斤`，可保存为日常价或优惠价；优惠价不知道原价时仍可保存。
2. 输入 `39.8 元、1.2 千克`，自动得到约 `16.58 元/斤`。
3. 现场输入 `32 元/千克`，可直接与页面上的元/斤历史价格比较。
4. 比价完成后点击“记录此价格”，价格和数量自动带入记录页。
5. 保存并新增后保留店铺、清空商品和价格、恢复日常价，并自动聚焦商品搜索。
6. 新增店铺或商品后可以立即选择；频繁使用后会自动进入常用区。
7. 新增“重百”并多次使用后，它可以替换常用店铺中的低频项。
8. 输入“永辉超市·金科店”后沿用永辉图标，但与其他永辉分店分别统计。
9. 保存错误记录后可以立即撤销，也可以稍后从历史记录编辑或删除。
10. 最近购买记录固定出现在首页最下方，补充星级后仍保留在列表中并显示评分。
11. 按单价输入 `32 元/千克` 并填写购买 `1.25 千克` 时，同时保留购买量并显示本次合计 `40 元`。
12. 商品详情价格区间只使用各店最新记录，超过 30 天的数据明确标注为较早记录。
13. 全部店铺趋势中各店独立连线，优惠价有独立标记，单店筛选只显示该店数据。
14. 搜索输入文字不会与搜索图标重叠；不存在的商品或店铺可直接添加。
15. 单位选择明显错误导致价格异常时提示用户确认，但允许保存真实价格。

## 13. 第一版明确不做

- 优惠条件、优惠类型和截止日期。
- 多维品质评价、评价文字和公开评论。
- 公共价格库、附近门店抓取和第三方促销信息。
- 条码扫描、票据 OCR 和自动识别商品。
- 品牌、规格、产地等复杂 SKU 管理。
- 自动计算“性价比分数”或替用户决定购买店铺。
- 跨重量、容量、个、盒、瓶之间的猜测换算。

这些能力只有在真实使用中反复出现明确需求后再评估，不进入当前最小实现。
